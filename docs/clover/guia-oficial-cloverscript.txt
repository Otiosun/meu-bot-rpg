♧┃GUIA OFICIAL - CLOVERSCRIPT 𖥔 CLOVER MULTICOLOR
     ── linguagem administrativa rígida para o bot ──

Status: GUIA FINAL APLICADO.
Aplicação no bot: APLICADO.
Objetivo: permitir que o dono/ADM faça, por comando, quase tudo que hoje exigiria abrir o código ou mexer manualmente no banco: recompensas, itens, estrelas, feitiços, árvore, hexágono, bônus, traços, status e ajustes administrativos.


_`─( ✓ )───── Premissa principal`_

CloverScript não é conversa natural.

Ele é uma linguagem rígida.

O bot não deve "adivinhar" o que o ADM quis dizer.
O bot deve:

> ler;
> validar;
> simular;
> avisar riscos;
> pedir confirmação;
> aplicar exatamente o que foi aprovado;
> registrar histórico.

Se uma linha estiver ambígua, o bot deve recusar.
Se o alvo não for seguro, o bot deve recusar.
Se o comando não existir na linguagem, o bot deve recusar.

O objetivo não é deixar o bot inteligente demais.
O objetivo é deixar o bot obediente, auditável e seguro.


_`─( ✦ )───── Comandos principais`_

O comando base será:

*.#clover*

Atalhos possíveis:
> .#cs
> .#script
> .#cloverscript

Comandos:

*.#clover simular*
> Lê o script, valida tudo e mostra o que seria aplicado.
> Não muda nada no personagem.

*.#clover aplicar*
> Aplica a última simulação válida feita pelo mesmo ADM no mesmo chat.
> Deve expirar em 30 minutos.

*.#clover aplicar codigo=XXXX*
> Aplica uma simulação específica, usando o código exibido pelo bot.

*.#clover cancelar*
> Cancela a última simulação pendente do ADM.

*.#clover validar*
> Só valida sintaxe e alvos.
> Não calcula impacto completo.

*.#clover modelo*
> Mostra modelos curtos de CloverScript.

*.#clover guia*
> Mostra um guia resumido no WhatsApp.

*.#clover historico @player*
> Mostra ações feitas via CloverScript naquele personagem.

*.#clover historico lote=ID*
> Mostra tudo que foi aplicado por um lote/script.


_`─( ◆ )───── Regra de segurança`_

O fluxo recomendado é sempre:

1. ADM manda:
> .#clover simular

2. Abaixo, envia o script.

3. Bot responde com a simulação.

4. ADM confere.

5. ADM manda:
> .#clover aplicar

6. Bot aplica e mostra o resultado.

Aplicar direto sem simulação não deve existir na V1.

Se um dia existir, deve ser apenas para owner e exigir:
> confirmar=true


_`─( ◇ )───── Formato geral`_

Todo script é feito por blocos.

Exemplo mínimo:

```txt
ALVO @Maksim
PH +60 fonte=spin_off teto=fora data=2026-06-24 motivo="Spin off aprovado"
FIM
```

Exemplo com vários alvos:

```txt
ALVOS @Maksim @Yuno @Noelle
PH +30 fonte=autonarrada teto=semanal data=2026-06-24 motivo="Autonarrada aprovada"
FIM
```

Exemplo com lote:

```txt
LOTE id="treino-touros-2026-06-24" nome="Treino dos Touros Negros" modo=rigido

ALVOS @Asta @Noelle @Magna
PH +30 fonte=treino_esquadrao teto=mensal data=2026-06-24 motivo="Treino de esquadrão aprovado"
YULLS +150 motivo="Participação no treino"
FIM
```


_`─( ⬡ )───── Regras de escrita`_

1. Uma ação por linha.

2. Linhas vazias são ignoradas.

3. Comentários começam com `//`.

Exemplo:

```txt
// recompensa do evento de sábado
PH +40 fonte=evento teto=fora data=2026-06-24 motivo="Evento especial"
```

4. Textos com espaço precisam de aspas.

Correto:

```txt
motivo="Spin off aprovado"
```

Errado:

```txt
motivo=Spin off aprovado
```

5. Datas devem usar o formato ISO.

Data:

```txt
2026-06-24
```

Data e hora:

```txt
2026-06-24 21:30
```

6. O fuso considerado é o horário do RPG/bot.
> Padrão: America/Sao_Paulo.

7. Valores booleanos usam:

```txt
true
false
```

8. Números não usam vírgula.

Correto:

```txt
YULLS +1500
```

Errado:

```txt
YULLS +1.500
```

9. O bot deve aceitar maiúsculas/minúsculas em palavras-chave, mas sempre exibir no padrão oficial.

10. O bot nunca executa SQL, JavaScript, eval, fórmula ou código bruto enviado pelo ADM.


_`─( ■ )───── Modos de execução`_

*modo=rigido*
> Padrão.
> Se qualquer linha falhar, nada é aplicado.

*modo=parcial*
> O bot aplica apenas blocos válidos.
> Cada bloco vira uma transação separada.
> Deve mostrar claramente o que foi aplicado e o que foi pulado.

*modo=auditoria*
> Só gera relatório.
> Não cria simulação aplicável.

Recomendação:
> V1 deve começar com `modo=rigido`.
> `modo=parcial` pode entrar depois.


_`─( 1 )───── Cabeçalho de lote`_

Um lote é opcional, mas recomendado.

Formato:

```txt
LOTE id="evento-x-2026-06-24" nome="Evento X" modo=rigido
```

Campos:

*id*
> Identificador único.
> Serve para impedir recompensa duplicada.
> Recomendado em recompensas para vários players.

*nome*
> Nome humano do lote.

*modo*
> rigido, parcial ou auditoria.

*data*
> Data padrão do lote.
> Ações sem data usam essa data.

Exemplo:

```txt
LOTE id="spin-off-lote-2026-06" nome="Spin offs de junho" modo=rigido data=2026-06-24
```

Regra:
> Se um lote tiver `id`, o bot deve bloquear reaplicação do mesmo lote, a menos que o owner use `confirmar=true`.


_`─( 2 )───── Alvos`_

CloverScript precisa saber com segurança quem será alterado.

Formas aceitas:

*ALVO @player*
> Melhor forma.
> Usa menção do WhatsApp.

*ALVO resposta*
> Usa o autor da mensagem respondida.

*ALVO id="5511999999999@s.whatsapp.net"*
> Usa ID exato.
> Owner/ADM avançado.

*ALVO tel=1234*
> Usa os últimos 4 dígitos.
> Só funciona se encontrar exatamente um player.

*ALVO nome="Maksim" confirmar=true*
> Usa nome/personagem.
> Só deve funcionar com confirmação, porque nome pode repetir.

*ALVOS @A @B @C*
> Aplica o mesmo bloco em vários players.

*ALVOS tel=1234 tel=5678*
> Vários alvos por últimos dígitos.

*ALVOS arquivo="lista-x"*
> Futuro.
> Lista salva pelo bot.

*TODOS jogo=liberado*
> Todos com jogo liberado.
> Owner apenas.

*TODOS esquadrao="Touros Negros" jogo=liberado*
> Todos de um esquadrão.
> Owner ou capitão autorizado, se o sistema permitir.

Regra de alvo:
> Se o alvo for ambíguo, o bot não aplica.
> Se um alvo de `ALVOS` falhar em `modo=rigido`, o lote inteiro falha.
> Em `modo=parcial`, só o alvo inválido é pulado.


_`─( 3 )───── Histórico e idempotência`_

Toda aplicação deve registrar:

> ID do lote;
> texto original do script;
> hash do script;
> ADM que simulou;
> ADM que aplicou;
> chat onde foi aplicado;
> data/hora;
> alvo;
> ação;
> valor anterior;
> valor novo;
> motivo;
> resultado.

Idempotência:

```txt
LOTE id="missao-vento-2026-06-24"
```

Se o mesmo lote for aplicado de novo, o bot deve responder:

```txt
Esse lote já foi aplicado.
Nada foi alterado.
```

Para reaplicar de propósito:

```txt
LOTE id="missao-vento-2026-06-24" confirmar=true
```

Essa reaplicação deve ser owner only.


_`─( 4 )───── Recompensas`_

_`─( 4.1 )───── PH`_

Formato:

```txt
PH +60 fonte=spin_off teto=fora data=2026-06-24 motivo="Spin off aprovado"
```

Remover PH disponível:

```txt
PH -10 motivo="Correção de recompensa duplicada"
```

Ajuste exato:

```txt
PH set disponivel=100 acumulado=500 motivo="Correção manual" confirmar=true
```

Campos:

*fonte*
> Origem da recompensa.

Fontes oficiais:

```txt
autonarrada
spin_off
missao_desenvolvimento
missao_esquadrao
treino_esquadrao
evento
retorno
admin
correcao
reembolso
penalidade
outro
```

*teto*
> Como a recompensa conta nos limites.

Valores:

```txt
semanal
mensal
fora
nenhum
```

Regras:

*teto=semanal*
> Conta no teto semanal.
> A semana começa na segunda-feira.

*teto=mensal*
> Conta no teto mensal da modalidade.

*teto=fora*
> Não conta no teto.
> Usar para retorno, evento especial, correção ou recompensa excepcional.

*teto=nenhum*
> Só deve ser usado em ajustes técnicos.

*data*
> Define em qual semana/mês a recompensa entra.
> Se não tiver data, usa a data do lote.
> Se o lote não tiver data, usa hoje.

*motivo*
> Obrigatório.

Simulação deve avisar:

> PH antes;
> PH depois;
> teto usado;
> se passou do teto;
> se bypassou teto;
> se a data cai em semana passada ou atual.

_`─( 4.3 )───── Estrelas`_

Player:

```txt

```

Esquadrão:

```txt
ESTRELAS +1 alvo=esquadrao motivo="Missão concluída"
```

Esquadrão específico:

```txt

```

Remover:

```txt

```

Regra:
> Se `alvo=esquadrao` e o player tem esquadrão definido, o bot usa o esquadrão do player.
> Se houver `esquadrao="..."`, usa esse esquadrão.


_`─( 5 )───── Inventário e itens`_

Dar item simples:

```txt
ITEM dar nome="Ticket de Feitiço" qtd=1 tipo=ticket motivo="Evento"
```

Dar item com descrição curta:

```txt
ITEM dar nome="Anel de Vidro Lunar" qtd=1 tipo=acessorio desc="Anel frágil recebido em missão." motivo="Recompensa narrativa"
```

Dar item com descrição longa:

```txt
ITEM dar nome="Anel de Vidro Lunar" qtd=1 tipo=acessorio motivo="Recompensa narrativa"
DESC
Um anel fino, quase transparente.
Ele não concede poder sozinho, mas serve como prova de uma missão concluída.
FIM_DESC
```

Remover item:

```txt
ITEM remover nome="Ticket de Feitiço" qtd=1 motivo="Usado para atualizar feitiço"
```

Definir quantidade:

```txt
ITEM set nome="Ticket de Feitiço" qtd=3 motivo="Correção" confirmar=true
```

Tipos sugeridos:

```txt
narrativo
ticket
consumivel
arma
acessorio
material
documento
evento
especial
```

Regra:
> Item não deve dar bônus mecânico sozinho.
> Se der bônus, precisa também criar/registrar um BONUS separado.

```txt
FEITICO adicionar
FICHA
♧┃FICHA DE FEITIÇO 𖥔 CLOVER MULTICOLOR
     ── avaliação rápida do grimório ──

_`─( ✓ )───── Identificação`_

*Nome do feitiço:*
> Mão de Lama
*Tipo:*
> Criação
*Versão:*
> v1

_`─( ✦ )───── Uso`_

*Custo:*
> Baixo a moderado
*Alcance:*
> Curto
*Duração:*
> 1 ação ou sustentação curta

_`─( ◆ )───── Efeito`_

*Descrição:*
> Cria uma mão de lama que agarra, puxa ou atrapalha um alvo próximo.

_`─( ◇ )───── Travas`_

> Não esmaga sozinha. Perde força contra alvo muito superior, calor intenso ou solo desfavorável.
```

Atualizar feitiço:

```txt
FEITICO atualizar nome="Mão de Lama"
FICHA

FIM_FICHA
```

Remover feitiço:

```txt
FEITICO remover nome="Mão de Lama" motivo="Substituído"
```

Regra:
> Feitiço não evolui automaticamente com o player.
> O script registra o estado atual aprovado.
> Nova versão precisa de atualização.

_`─( 25 )───── Guia para qualquer IA`_

Quando uma IA for escrever CloverScript, ela deve obedecer estas regras:

1. Não invente comandos fora deste guia.

2. Sempre use `.#clover simular` antes de qualquer script.

3. Sempre use `motivo="..."` em ações que alteram personagem.

4. Sempre use data ISO:
> 2026-06-24

5. Prefira alvo por menção:
> ALVO @player

6. Se não houver menção, use:
> ALVO tel=1234

7. Não use nome puro sem:
> confirmar=true

8. Para recompensas em lote, sempre crie:
> LOTE id="..."

9. Se for recompensa repetível, use um ID único por evento/data.

10. Se tiver descrição longa, use:
> DESC / FIM_DESC

11. Se tiver ficha de feitiço, use:
> FICHA / FIM_FICHA

12. Não use `PH set`, `PLAYER resetar`, `PLAYER arquivar`, `TRACO raro`, `CATALOGO criar` sem confirmar que o dono pediu.

13. Se faltar informação, pare e pergunte.

14. Não tente corrigir sozinho valores de teto, requisito ou regra do RPG.

15. Escreva scripts pequenos quando a ação for perigosa.


_`─( 26 )───── Gramática resumida`_

Esta gramática é conceitual.

```txt
SCRIPT        = CABECALHO? BLOCO+
CABECALHO     = "LOTE" KV*
BLOCO         = ALVO_LINHA ACAO+ "FIM"
ALVO_LINHA    = "ALVO" TARGET | "ALVOS" TARGET+
TARGET        = MENTION | "resposta" | "id=" STRING | "tel=" DIGITS | "nome=" STRING
ACAO          = PH | YULLS | ESTRELAS | ITEM | BONUS | FEITICO | HEXAGONO | ARVORE | RETORNO | ESQUADRAO | ANTIGHOST | ATRIBUTO | TRACO | STATUS | PERSONAGEM
KV            = KEY "=" VALUE
VALUE         = WORD | NUMBER | STRING | BOOLEAN | DATE
STRING        = texto entre aspas
DATE          = AAAA-MM-DD ou AAAA-MM-DD HH:mm
```

Palavras desconhecidas:
> erro.

Campo obrigatório ausente:
> erro.

Alvo ambíguo:
> erro.

Permissão insuficiente:
> erro.

_`─( ✓ )───── Conclusão`_

CloverScript deve virar a linguagem de administração do Clover Multicolor.

Ela permite que o dono faça pelo WhatsApp o que hoje exigiria mexer no bot por dentro, mas sem virar bagunça.

A ordem correta é:

> escrever rígido;
> simular sempre;
> aplicar só depois;
> registrar tudo;
> recusar ambiguidade.

O poder da linguagem vem justamente do limite.

Ela não conversa.
Ela executa o que foi escrito certo.


_`─( 30 )───── Atualização de alvos`_

Status: APLICADO.

A identidade principal de um player é o `player_id` salvo no banco.

O telefone deixou de ser a identidade principal.
Ele continua existindo apenas como fallback.

Ordem recomendada de alvo:

> menção real do WhatsApp;
> resposta a uma mensagem do player;
> `player_id`;
> alias vinculado;
> nome do personagem;
> telefone ou últimos dígitos.

*ALVO resposta*
> Funciona dentro do CloverScript.
> Usa o autor da mensagem respondida pelo ADM.
> Se a mensagem não for uma resposta real, o bot recusa.

*Alvo composto*

```txt
ALVO tel=1234 personagem="Nome"
```

> Serve para reduzir ambiguidade.
> O bot só aplica se conseguir resolver com segurança.

*Comando de diagnóstico*

```txt
.#quem @player
```

> Mostra qual cadastro o bot encontrou.
> Mostra fonte da resolução: menção, resposta, alias, telefone, nome ou fallback.
> Mostra aliases vinculados ao player.

*Comando rápido de recompensa*

```txt
.#recompensa @A @B ph=40 motivo="Evento"
```

> Dá PH para todos os players marcados.
> Usa o mesmo histórico de PH e o mesmo resolvedor de alvos.
> Para lote complexo, prefira CloverScript.

*Comando de correção*

```txt
.#vincular @player personagem="Nome do Personagem"
```

> Vincula a menção, LID, telefone ou alias ao `player_id` correto.
> Deve ser usado quando o WhatsApp trocar `@lid`, espelhar contato ou quando o bot resolver a pessoa errada.

Regra:
> comando desconhecido continua recusado;
> alvo ambíguo continua recusado;
> erro de alvo deve mostrar a linha e o alvo que falhou sempre que possível.

_`-( 31 )----- Identidade definitiva Clover`_

Status: APLICADO.

Regra principal:
> telefone nunca é identidade principal.
> telefone é só alias/fallback.
> ação mecânica sempre aplica no `player_id` canônico.

O resolvedor central retorna:

```txt

player

source

```

Todo comando mecânico deve passar por ele:

```txt
BONUS

STATUS

```

Se o alvo encontrado estiver sem personagem real, o bot recusa:

```txt

```

Conta como sem personagem:
> vazio;
> `-`;
> `.`;
> `Cacador`.

Tipos de alias salvos:

```txt

jid
phone
phone_last4
character
manual
whatsapp_mention
```

Campos novos no player:

```txt

is_shadow
identity_status
```

Cadastro sombra:
> não deve receber recompensa, feitiço, árvore, traço, status ou hexágono.
> serve apenas para redirecionar para o cadastro canônico.


_`-( 32 )----- Correção de identidade`_

Diagnosticar:

```txt
.#quem @player
.#quem 2280
.#quem personagem
```

Vincular:

```txt
.#vincular @player personagem="Nome do Personagem" tel=8599136380
```

Faz:
> resolve a menção;
> resolve o personagem canônico;
> cria alias de `lid/jid`;
> cria alias de telefone;
> cria alias de últimos 4 dígitos;
> se o telefone achar cadastro espelho sem personagem, mescla no canônico.

Se a menção ou telefone já apontar para outro personagem real:
> o bot recusa;
> não mescla no automático.

Mesclar manualmente:

```txt
.#mesclarplayer origem=558599136380@s.whatsapp.net destino=65902615761026@lid motivo="Cadastro espelho"
```

Faz:
> move aliases da origem para o destino;
> cria aliases da origem apontando para o destino;
> marca origem como `is_shadow=true`;
> define `merged_into=destino`;
> impede recompensa futura na origem;
> preserva histórico econômico antigo sem somar automaticamente.

_`-( 34 )----- Recompensa segura`_

Recompensa simples agora simula primeiro.

Por marcados:


Por lista:

> linha;

> fonte da resolução;
> cadastro encontrado;
> motivo da recusa;
> sugestão de correção.
